# PLAN-web — review of mvd-web

Overall assessment: mvd-web is a competent, feature-dense vanilla-JS frontend with a clean Go/WASM boundary (`cmd/wasm/main.go` is thin and well-documented, `worker.js` is small and purposeful), and it has already consolidated several rendering paths well (`renderDivergingGraph`, `renderSpansTimeline`, `renderHeatmapTable`, `renderTableRows`, one orbit-camera projection for the whole map). The dominant structural problem is that `static/app.js` is a 10,811-line single global script with ~15 top-level mutable state objects and a hand-maintained 165-line reset routine; correctness is generally good, but I found four real bugs (deferred-bucket playhead reset, a `pent`/`pe` field mismatch, a worker promise-correlation race, and a misaligned fallback scoreboard), a body of dead code (~120 lines JS + ~70 lines CSS), and several two-to-five-way duplications (scanline sampler, canvas tooltips, hub replay URLs, binary searches, duel detection) that are cheap to collapse. No violations of the canonical TEAM_COLORS convention were found in the JS — the convention is followed carefully — though two small color nits exist at the CSS edge.

## Big picture

- **A1 — app.js is a monolith and should be split into ES modules.** 10,811 lines in one `<script src="app.js">` (not `type="module"`), so every function and state object is a page global. The file already has crisp internal seams (theme constants, worker bridge, hub client, summary tables, timeline graphs, chat, map renderer, map interaction, learn mode, loc graph, heatmaps, playback — see the `─── section ───` banners). Splitting along those exact banners into ~10 ES modules loaded via one `type="module"` entry would need no framework, no bundler (native ESM works on a static host), and would make the implicit dependency graph (who reads `timelineState`, who writes `mapState`) explicit through imports/exports. Impact: extensibility.
- **A2 — state is a set of ad-hoc global stores mutated from many places, and reset is manual and drifty.** `currentResult`, `timelineState` (app.js:2775), `mapState` (6009), `_wtc` (6760), `locGraphState` (9773), `airgibState` (1936), `packDropsState` (2074), `weaponGraphHitState` (3518), `powerupGraphHitState` (5120), `_itemsPanelState` (8910), plus loose flags (`chatRendered`, `precomputedFrags`, `pickupsMode`). `resetUIToCleanState()` (2796–2960) is a 165-line hand-maintained wipe list that must be updated whenever any panel gains state; the `if ('controlRegions' in mapState)` guards at 2941–2946 and the double canvas-clearing shared with `resetTimelineState()` (2846–2853 vs 3003–3009) show it has already drifted. Suggested: give each module an `init(result)`/`reset()` pair and have `displayResults` iterate a registry, so forgetting a reset becomes structurally impossible. Impact: extensibility/correctness.
- **A3 — `setCurrentTime` fans out to every tab unconditionally.** app.js:504–517 calls `updateTeamStatus`, `updateMapLegend`, `updateRegionStatus`, `updateItemsPanelStatus`, `renderChatMessages`, and `renderMap` on every playhead change — including per-mousemove while scrubbing — regardless of which tab is visible. Only `renderMap` has a skip guard. Hidden-tab DOM rebuilds (team status tables, region status rows with fresh canvases) are wasted work on every scrub tick. Suggested: a small subscriber model (`onTimeChange` handlers registered per tab, invoked only for the active tab, with a "stale" flag consumed on tab switch — the tab-switch handler at 697–713 already re-renders the incoming tab). Impact: performance/extensibility.
- **A4 — the deferred-buckets second pass re-enters full init paths and simulates a click.** `applyDeferredBuckets` (289–328) re-runs `initRegionControlData` / `displayTimelineAnalysis` / `initMapView` and then does `active.click()` to repaint the current tab. Re-entering full initialisers has side effects that were designed for first load (see F1), and the synthetic click re-triggers the tab handler's triple-render (immediate + rAF + 120 ms). Suggested: split "install per-demo data" from "apply bucket-derived data" so the second pass only does the latter, and call the tab's render function directly instead of clicking. Impact: correctness/readability.
- **A5 — worker RPC uses single-slot resolve callbacks with no request correlation.** `analyzeResolve` / `recomputeResolve` / `losResolve` (88–94) are module-level singletons; see F3. Impact: correctness.
- **A6 — rendering architecture is sound; canvas/DOM split is right.** Time-series and the map are canvas (with dpr-aware `setupGraphCanvas` and the floor-model bitmap cache in `drawCachedWorld` doing the right thing); tables/heatmaps are DOM with one shared sortable-table implementation. The remaining problem is not architecture but residual copy-paste inside the canvas layer (F7, F8).
- **A7 — TEAM_COLORS convention: followed.** Every team-coloring site I checked routes through `TEAM_COLORS` indexed by `timelineState.teams` order (`getTeamOrder` 1634, `timelinePlayersByTeam` 3577, map `playerSymbols[].teamIdx` 7047, heatmap header underlines 10640, powerup/region legends 5150/5243, score colors 4088). Two edge nits: (a) `styles.css:109–110` hardcodes `#ff5050`/`#50a0ff` for `.topbar-team-a/b` instead of `var(--team-a/--team-b)`, silently forking the CSS mirror; (b) the team *order* itself is computed in `displayResults` (1064–1070) from `demoInfo.players[].stats.frags`, while the scoreboard treats `match.players[].frags` as the corrected authoritative count (1299–1310) — in a telefrag-heavy demo the "winning team = index 0" color assignment could disagree with the displayed corrected totals. Consider sourcing the sort from `match.players` with demoInfo fallback.
- **A8 — runtime CDN dependencies without integrity pins.** `index.html:12–15` loads Cytoscape + fcose from unpkg and lines 7–9 load Google Fonts. No SRI hashes, no version lockfile, and the Locs & Regions tab silently degrades if unpkg is unreachable (guard at app.js:10130). This also contradicts the README's "the rest of the frontend is dependency-free JS" claim. Suggested: vendor the four files into `static/vendor/` (they are copied to dist anyway) or at minimum add `integrity`/`crossorigin` attributes. Impact: correctness (deploy reliability).

## Findings

- **F1 — Deferred bucket arrival resets the playhead to 0, clobbering `?t=` deep links and early scrubbing.** `displayTimelineAnalysis` sets `mapState.currentTime = 0` (app.js:3056) and `initMapView` does the same (6350). Both are re-run by `applyDeferredBuckets` (316–317) a few seconds *after* `displayResults` → `applyUrlState` has applied a `?t=` deep link (589–595) — so the user is yanked back to 0:00 (and the debounced `updateUrlState` then strips `t` from the URL). Any manual scrub during the deferred window is lost the same way. Suggested change: remove the `currentTime = 0` writes from the re-runnable initialisers (reset already happens in `resetUIToCleanState`, 2928), or have `applyDeferredBuckets` save/restore `mapState.currentTime` around the re-init. Impact: correctness.
- **F2 — Team Status panel can never show Pent: wrong field name.** `updateTeamStatus` reads `hasPent: … (data.pent ?? data.hasPent ?? false)` (app.js:5312), but the columnar reconstruction emits the pentagram flag as `pe` (`COLUMNAR_BOOL_FIELDS`, 3147; consumed correctly as `data.pe` by `getActiveBadges`, 6079). Neither `pent` nor `hasPent` exists on the reconstructed player object, so the "Pent" tag in the Weapons column (5360) is dead. Fix: `data.pe ?? false`. Impact: correctness.
- **F3 — Worker request/response correlation race: single-slot resolvers.** `analyzeResolve`/`recomputeResolve`/`losResolve` are overwritten by each new call (app.js:256, 336–337, 348–349). If a second `analyzeInWorker` (e.g. the user clicks two search rows in quick succession) or a second `applyRegionConfig` recompute is issued before the first reply arrives, the first worker reply resolves the *second* caller's promise with the *first* request's data, and the second reply is dropped (`recomputeResolve` is already null) — stale stats rendered, one promise never settles. Suggested change: attach an incrementing `reqId` to each `postMessage` and key pending resolvers in a `Map`, or serialise calls through a one-deep queue. Impact: correctness.
- **F4 — `displayScoreboardFallback` rows are misaligned with the scoreboard header.** The fallback (app.js:1586–1630, used when `demoInfo` is absent) emits 13 `<td>` per row, but the `#scoreboard` header (index.html:240–257) has 16 columns (Player, Team, HC, Frags, Eff, Kills, RL K, LG K, Deaths, TK, Bores, Dmg, Taken, Ewep, ToDie, Ping). Cells land under the wrong headers from "Eff" onward, and the handicap column is never hidden on this path (only `displayPlayerStats` toggles it, 1320–1322; there is no default CSS hiding `.handicap-col`). Fix: emit one cell per current header (with `-` fillers) and hide `.handicap-col` here too. Impact: correctness.
- **F5 — Three competing `escapeHtml` definitions; the last silently wins for all call sites.** Definitions at app.js:887 (null-safe regex), 2675 (DOM-based, returns `''` for any falsy value including `0`), and 10325 (regex, **no** null guard — `escapeHtml(null)` returns the string `"null"`). Function declarations hoist, so 10325 is the only one that ever runs; callers written against the earlier null-safe contracts are one refactor away from rendering `"undefined"` into the page. Keep exactly one (the 887 variant, which handles nullish and non-strings), delete the other two. Impact: correctness/bloat.
- **F6 — Dead code: a whole feature panel plus assorted stragglers.** (a) `buildMapPowerupList` (app.js:10775–10811) targets `#map-powerup-events`, which does not exist in index.html — the function early-returns every time; its call at 6340 and the supporting `.map-powerup-list` CSS block (styles.css:3018–3086) are dead too. (b) `legend-team-a`/`legend-team-b` setters (app.js:3061–3062) reference IDs absent from index.html. (c) `#map-timeline-slider` lookup (6351–6352) — element does not exist. (d) `timelineState.buckets` (2776) and `overviewBucketSize` (2783) are never read. (e) `.player-red`/`.player-blue` (styles.css:3064–3070) are referenced nowhere. Delete all of it (~190 lines). Impact: bloat.
- **F7 — The scanline "hold-last sample" renderer is copy-pasted three times.** The identical `cursor`/`sampleAt` closure plus the integer-snapped stacked-segment fill loop appears in `renderDivergingGraph` (app.js:3352–3415), `renderMiniStack` (3650–3680), and `renderMiniDiverging` (3852–3889). Extract a `makeScanlineSampler(points)` helper and a `fillStackedColumn(ctx, px, segs, from, dir, scale)` helper; the three renderers reduce to setup + orientation. Impact: bloat/readability.
- **F8 — Canvas tooltip infrastructure duplicated, with layout constants forked between renderer and hit-tester.** `attachWeaponGraphTooltip` (app.js:4849–4910) and `attachPowerupTimelineTooltip` (5173–5223) each create the tip div, run a mousemove hit-test, and clamp-position with the same code (4902–4907 ≡ 5215–5220); the loc-graph tooltip (10248–10274) is a third variant. Worse, the weapon tooltip re-declares the graph's layout constants (`PAD/AXIS_H/H=200/DROP_STRIP_H`, 4862–4868) that must be kept in sync with `renderDivergingGraph` (3303, 3310–3320) by hand — the comment admits it. Extract `attachCanvasTooltip(canvas, hitTest, renderHtml)` and move the diverging-graph layout numbers into one shared const object used by both sides. Impact: bloat/correctness-risk.
- **F9 — Hub replay URL built inline in five places.** app.js:1850, 1902, 2002, 2586, 5398 all interpolate `https://hub.quakeworld.nu/games/?gameId=…&from=…&to=…&track=…` with subtly repeated `demoOffset` handling. One `hubReplayUrl({gameId, from, to, track})` helper (plus the existing `buildHubWatchLink` reworked on top of it) removes the drift risk when the hub URL scheme changes. Impact: bloat.
- **F10 — Per-tick DOM/canvas churn in the time-sync path.** (a) `updateRegionStatus` (app.js:7256–7367) rebuilds its rows and calls `buildPlayerRegionIcon` (7371–7396), which creates a **new `<canvas>` element per player per call** — and it runs on every `setCurrentTime` (513) and every 200 ms during playback (10770). (b) `updateTeamStatus` runs **twice** per `setCurrentTime`: once directly (510) and once at the tail of `updateTimeIndicators` (4620, called at 509); the same double-call happens in `animatePlayback`'s full-sync (10767–10768). Suggested: drop the direct call at 510 (or the one in `updateTimeIndicators`), and cache the region icons per (player, badge-set) or draw them into persistent canvases. Impact: performance.
- **F11 — Per-interaction re-sorting and unthrottled pan re-renders.** `prepScoreData` clones and sorts the entire frag-event list on every render (app.js:4066), and pan drag (4162–4180) calls `setViewRange` → `updateDetailView` → all five graph preps/renders on every mousemove with no rAF coalescing — each render also resizes its canvas (`setupGraphCanvas` writes `canvas.width`), forcing layout. Sort `fragEvents` once at intake (they are already sorted once in `precomputeFragCounts`, 5483) and coalesce pan-drag view updates into one per animation frame. Impact: performance.
- **F12 — Chat rebuild leaks a scroll listener and a duplicate time-line element per demo load.** `buildFullChat` adds a new `scroll` listener to the persistent `#chat-scroll-viewport` on every rebuild (app.js:4737–4742) and unconditionally appends a new `#chat-current-time-line` div to `.chat-scroll-inner` (4728–4734); `resetUIToCleanState` clears the message containers but not the inner wrapper (2860–2862), so both accumulate across demo loads (the stale line divs render at top:0). Guard both with a `dataset`/lookup check, mirroring the `_toggleWired` pattern used elsewhere. Impact: correctness (minor)/bloat.
- **F13 — Undocumented chat dedupe filter conflicts with the "surface authoritative data" rule.** `buildFullChat` silently drops any message whose exact text repeats within 3 s (app.js:4697–4704). Per CLAUDE.md, deliberate filters need a why-comment naming the invariant or incident (presumably server double-prints); as written it also swallows a player genuinely sending the same bind twice. Either document the motivating duplication (and ideally scope it to `type === 'frag'` if the target is duplicated obituary prints) or remove it. Impact: correctness/convention.
- **F14 — A second, parallel table-sorting implementation for airgibs only.** The airgibs table has its own sort state machine, indicator classes, and render loop (`airgibState`/`renderAirgibs`/`initAirgibSorting`, app.js:1936–2055) while every other table uses `makeSortable` (1147). `makeSortable` already supports `data-sort-value` for numeric keys, which covers the airgib columns; converting the airgibs table removes ~90 lines and one concept. Impact: bloat/extensibility.
- **F15 — Small logic fragments duplicated 3–5×.** (a) Duel detection `players.every(p => p.team === p.name)` at app.js:1380, 9861, 10471 — extract `isDuel(result)`. (b) Team frag totals from `demoInfo.players` at 907–911, 1066–1069, 1228–1235 — extract `teamFragTotals(players)`. (c) Four hand-rolled "last index with t <= time" binary searches: `getFragsAtTime` (5495–5502), `moverPoseAt` (7566–7577), `streamPosAt` (8330–8339), `trailIndexAtTime` (9005–9014) — extract one `lowerBoundIndex(times, t)` (two operate on `{time}` objects, two on parallel arrays; a comparator or accessor parameter covers both). (d) The frag-sort `[...players].sort((a,b) => (b.stats?.frags||0)-(a.stats?.frags||0))` appears 5× (1553, 1662, 1713, 1743, 2195). Impact: bloat/readability.
- **F16 — Worker re-parses the entire result JSON to derive default regions; Go bridge repeats marshal boilerplate 8×.** worker.js:198 runs `JSON.parse(jsonStr)` over the full multi-MB result purely to read `timelineAnalysis.regionControl.regions` for the deferred recompute — the Go side still holds `lastResult`; an argument-less `recomputeRegionControl()` defaulting to the stored regions would remove the parse (it is off the critical path but still seconds of worker time on big demos). Also the empty `catch` blocks at worker.js:190–192 and 209–211 swallow errors without logging. In `cmd/wasm/main.go`, every export repeats the same `json.Marshal` + `errorJSON` envelope (e.g. 121–127, 146–164, 183–188, 205–212, 228–235, 251–257, 306–310) — a `func respondJSON(v any, err error) any` helper cuts ~50 lines. Impact: bloat/performance.

## Low priority / nits

- `styles.css:109–110`: `.topbar-team-a/b` hardcode `#ff5050`/`#50a0ff`; use `var(--team-a)`/`var(--team-b)` so the CSS mirror stays single-source (see A7).
- LOS/PVS one-way colors (app.js:9081–9092) are red/blue by *pair order*, visually identical to the team palette while explicitly not encoding team — the comment admits it; consider a hue that cannot be mistaken for team identity (e.g. orange/green).
- `resetUIToCleanState` guards `weaponGraphHitState`/`powerupGraphHitState` with `typeof … !== 'undefined'` (app.js:2952–2959); both consts are defined in the same file and the function only runs post-parse — the guards are noise.
- Eye-height literal `22` inline in `drawVisLines` (app.js:9113–9114) and the `2500` u/s teleport threshold in `precomputeFullTrails` (7948) deserve named constants next to `PLAYER_ORIGIN_ABOVE_FLOOR`.
- `applyDeferredBuckets` repainting via `active.click()` (app.js:322) also re-fires `updateUrlState` and the Firefox triple-render; call the tab's render function directly (folded into A4).
- Four separate time-axis implementations: `drawXAxisTicks` (canvas), `renderSharedTimeAxis` (DOM), `renderUnifiedAxis` (DOM, and the only one not using `pickTickInterval` — its tick count is duration-based), `renderChatTimeAxisFull` (vertical, fixed 5 s ticks that get dense on long demos). At least route `renderUnifiedAxis` through `pickTickInterval`.
- `switchTab`'s triple render (immediate + rAF + 120 ms, app.js:711–713) is a documented Firefox-snapshot workaround — fine, but it also runs for tabs that don't need it (e.g. `loc-graph` triple-fits the cytoscape view); consider scoping to the canvas tabs.
- The Supabase anon key inline (app.js:357) is a public anon key so this is acceptable, but a one-line comment saying so would pre-empt the next reviewer's alarm.
- `formatDuration` (app.js:2648) renders negative times oddly (`Math.floor` of negatives); callers currently clamp, but a `Math.max(0, seconds)` inside would make it total.
- `getWeaponName` (2654) and `SEARCH_MODE_LABELS` (879) are near the code that uses them rather than the theme-constant block at the top that claims to be "the single source of truth for constants"; either move them up or soften the header comment.
- index.html's WASM-loading overlay uses a large inline `style` block (19–25) while everything else lives in styles.css; move it to a class for consistency.
- `worker.js` `logWorkerTimings` and app.js `finishLoadTiming` both re-derive loc/bsp totals with the same reduce (worker.js:101–102, app.js:142–143) — trivial, but the timing payload could carry the sums.
